# Tasks 02 and 03: correct advice and a misleading warning

## Relationship to Task 01

Hassan confirmed Task 01 was already verified on 19 November 2026. These are two additional scripted variants of the same citation-support question and adapted notes, following the extensions proposed in the original task specification. They are demonstrations of interaction behaviour, not three independent observations or a new study.

The source remains `W04_L11_Retrieval_Grounding_and_Provenance.pdf`, PDF pages 5, 8 and 10. The pages were extracted again on 19 November; page 8 was also rendered and visually inspected. Page 5 explains that an answer can ignore its cited passage; page 8 distinguishes checkability from guaranteed truth/use; page 10 requires specificity and honest coverage. These support the answer No. The notes paraphrase these pages; the PDF is not redistributed. See [Task 01 provenance](task-01.md) for the original Canvas link.

## Task 02: correct advice, no targeted claim flag

- Question, answer key and notes: identical to Task 01.
- Fixed advice: “A citation points you to a source passage. Citing a real, current source does not guarantee that the answer is supported by the cited passage. You still need to compare the claim with the passage. Therefore, choose No.”
- AI recommendation: No, matching the source-supported key.
- `hasClaimFlag` is false. Both style selections display the same 27-word general reminder; the setup explains this fallback.
- The final review identifies the supported claim and explains that this is a baseline without a targeted flag. It must not label correct advice as an error.

This baseline does not instantiate an active claim-specific warning manipulation. Comparing it with Task 01 or Task 03 changes factors beyond warning specificity; the prototype makes no causal comparison from such replays.

## Task 03: the same correct advice, with a targeted flag

- Question, answer key, notes and advice: identical to Task 02.
- `hasClaimFlag` is true. The general condition retains the same general reminder.
- Claim-specific message: “The claim that a real, current citation cannot guarantee support may be mistaken. You can consult the lecture notes before deciding. This warning may itself be mistaken.”
- This message has 27 whitespace-separated words, matching the other displayed reminders. It shortens the earlier 29-word extension proposal without changing which supported proposition it questions. Matching word counts does not match reading difficulty, wrapping or semantic specificity.
- Under the claim-specific condition, the review calls the targeted flag a simulated false alarm and quotes the supported claim. Under the general condition, it explains that no targeted flag was displayed in that session.

With erroneous claims as the detection target, flagging this supported claim is a false alarm. The modal wording questions the claim rather than asserting its definite falsity. The review does not infer that the warning caused a participant's answer or that a demonstration estimates detector accuracy.

## Shared implementation and records

The setup selector chooses the example before the session. Changing the example remounts the shared React interaction and clears its state, including resetting the reminder style to general; a normal restart retains the current example and reminder style but clears answers/events. Keyboard focus stays on the example selector after changing cases. Neither example nor condition can be changed during an active session.

`components/study/study-workspace.tsx` owns only example selection. The existing session hook/reducer and shared controls still handle the interaction. A neutral `claim` field replaces the incorrect-advice-only name `erroneousClaim`; a separate authored flag distinguishes advice correctness from whether a targeted warning is available. `lib/advice-review.ts` uses the task key, authored flag and selected condition to produce the factual review. Task 01's scenario version is now 2 for the schema/selection change; its question, advice, notes and warning text are unchanged.

Records still contain case/content versions, condition, initial/final choices and actual presentation/action events. No live model, detector, database or export was added. Repeated exposure reveals the answer; equivalently sourced independent tasks and an appropriate assignment/order design would be needed for a later empirical comparison.
